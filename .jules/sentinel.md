
## 2026-08-29 - [XSS via IPC Boundary in UDP Discovery]
**Vulnerability:** Untrusted UDP LAN packets parsed via JSON.parse in the backend (Electron main process) were sent directly to the frontend via IPC. While mapped to a TS interface (`DiscoveredServer`), properties like `players` or `phase` were passed uncoerced (e.g. as strings instead of numbers). In the frontend, the UI rendered these fields via `.innerHTML` without escaping or strict type coercion, trusting the TS types and opening an XSS vector from the local network.
**Learning:** TypeScript typings for IPC boundaries and parsed JSON can create a false sense of security. Just because an interface specifies `players: number` does not mean `JSON.parse` or IPC will enforce it at runtime. This disconnect masks XSS vulnerabilities if the frontend assumes the data is safe to embed directly into the DOM based solely on its TS type.
**Prevention:** Apply strict type coercion (e.g., `Number()`, `String()`) immediately upon parsing untrusted data before it crosses the IPC boundary. Additionally, implement defense-in-depth on the frontend by escaping all dynamic text rendered via `.innerHTML`, even if the property is typed as a primitive like a number or a strict literal.
